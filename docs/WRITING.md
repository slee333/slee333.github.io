# 글쓰기와 발행

## 평소에는 이렇게 요청하세요

노션에서 원고를 완성한 뒤 이 프로젝트에서 다음처럼 요청하면 됩니다.

> 이 노션 글을 가져와서 변경사항과 미리보기를 보여줘: [노션 링크]

미리보기를 본 뒤:

> 이 검토본을 블로그에 반영해줘.

공개 사이트에 올릴 준비가 되면:

> 이번 글과 필요한 이미지만 커밋하고 배포해줘.

가져오기·미리보기는 기존 발행본을 바꾸지 않습니다. `apply`도 로컬 파일만 반영하며, Git 커밋이나 푸시는 하지 않습니다. 현재 프로젝트에 다른 작업이 함께 있으므로 `git add .`로 전체를 한꺼번에 발행하지 마세요.

## 노션 원고

원고의 기준은 노션입니다. 발행 후 고칠 때도 노션에서 수정하고 다시 가져오세요.

- **title**: 제목. 노션의 기본 제목 속성도 인식합니다.
- **categories**: `life`, `learning`, `research`, `cifellowship` 중 하나.
- **date**: 발행일. 비워두면 가져온 날의 UTC 날짜입니다.
- **lang**: `kr`(기본), `en`, `es`.
- **subtitle**: 한 줄 요약. 비워도 됩니다.
- **translation_id**: 같은 글의 번역본들이 공유하는 고정 ID. 발행 후 바꾸지 마세요.
- **filename**: 새 글의 영문 파일 이름. 선택 사항입니다.
- **tags**: 선택 사항입니다.
- **image**: 대표 이미지 파일/URL. 없으면 노션 커버, 둘 다 없으면 이미지 없이 발행합니다.
- **featured**: 체크한 글을 홈 대표 글로 우선 사용합니다. 최근 글부터 최대 2개를 보여주며, 자리가 남으면 `_data/home_featured.yml`의 기본 추천으로 채웁니다.

한국어 글을 먼저 발행하고, 필요한 글만 번역하세요. 이 도구는 번역문을 자동 생성하지 않습니다. 번역 원고에는 같은 translation_id와 다른 lang을 지정하면 언어별 주소를 생성합니다. 기존 글의 주소는 다시 가져와도 유지합니다.

## 최초 설정

프로젝트의 `docs` 폴더에서 실행합니다.

```powershell
python -m pip install -r requirements-writing.txt
```

`docs/.env`에 `NOTION_TOKEN`을 설정하고, 가져올 노션 페이지에 해당 연결의 읽기 권한을 부여하세요. 기존 토큰을 그대로 사용할 수 있습니다. `.env`는 커밋하거나 공유하지 않습니다.

새 이미지는 Cloudinary에 업로드하지 않고 블로그의 `assets/images/posts/`에 저장합니다. 같은 이미지 내용은 같은 파일 이름을 사용하므로 재가져오기 시 발행 저장소에 중복 파일이 생기지 않습니다. 노션의 만료되는 이미지 주소는 발행본에 남기지 않습니다. 기존 글의 Cloudinary 이미지는 그대로 유지됩니다. 사진이 많으면 저장소가 커지므로 업로드 전 적절히 줄여 주세요. 이미지 한 장의 가져오기 상한은 25 MB입니다.

## 직접 실행하기

```powershell
python new_blog_workflow.py import "노션 페이지 URL"
```

카테고리 속성이 없는 일반 페이지라면 `--category life --slug new-york-weekend`를 덧붙이세요. 결과에 표시되는 검토 ID를 아래 명령의 `검토ID` 자리에 넣습니다.

```powershell
python new_blog_workflow.py review 검토ID
python new_blog_workflow.py preview 검토ID
```

미리보기는 원본 사이트를 별도로 복사해 만듭니다. 기본 주소는 `http://127.0.0.1:4001`이며, 명령이 출력하는 해당 글 주소를 여세요. 기존 4000번 미리보기와 분리됩니다. 종료는 Ctrl+C입니다. 이미 사용 중인 포트라면 `--port 4002`로 변경할 수 있습니다.

```powershell
python new_blog_workflow.py apply 검토ID
bundle exec jekyll build
bundle exec jekyll doctor
```

`apply`는 가져온 시점 이후 로컬 글이 바뀌었으면 덮어쓰지 않고 중단합니다. 그때는 노션 원본에 수정사항을 합친 다음 다시 가져와 차이를 검토하세요. 적용 전 원본은 검토 폴더의 `before.md`에 보관됩니다. 검토본을 직접 고치기보다 노션에서 수정 후 다시 가져오는 흐름을 권장합니다.

최종 Git 변경사항에서 해당 글과 필요한 이미지, 의도한 디자인 변경만 선택해 커밋·푸시합니다. 실제 공개 여부는 GitHub Pages 배포 완료 후 확인합니다.

## 지원 범위와 보관

본문·제목·링크·강조·코드·중첩 목록·체크리스트·인용·콜아웃·토글·표·이미지·캡션을 변환합니다. 노션 컬럼은 읽기 순서로 합칩니다. 임베드는 링크로 표시합니다. 동영상·첨부 파일 등 지원하지 않는 블록이 있으면 조용히 누락하는 대신 가져오기를 중단합니다.

변환 파일은 Jekyll Markdown 컨테이너 안에 HTML로 본문 구조를 보존합니다. 코드 안의 Liquid 문법은 실행되지 않도록 처리합니다.

`.blog-workflow/`에는 원고·이미지·백업·미리보기 복사본이 있습니다. Git과 사이트 빌드에서 제외됩니다. 오래된 검토/미리보기 폴더는 필요가 없어졌을 때 삭제해 용량을 정리할 수 있습니다.

구현 참고: [Notion 블록 가져오기](https://developers.notion.com/reference/get-block-children).
