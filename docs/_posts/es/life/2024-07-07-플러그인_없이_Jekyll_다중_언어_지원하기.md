이번에 새롭게 블로그를 시작하며 자그마한 욕심이 생겼다. 블로그를 우리말, 영어, 그리고 스페인어 (!) 로 지원 해 보고 싶다는 생각이었다.

새롭게 블로그를 시작하는 플랫폼으로는 Jekyll을 선택하였는데, Jekyll에서 흔히 사용하는 **multiple-languages-plugin**이나 **polyglot**은 내가 사용하려 하니 여러가지 애로사항이 있었다. 포스트 및 페이지를 하위 폴더로 분류해서 저장해야 하는데 이 부분이 Jekyll에 인식되지 않는 문제였다. 사이트맵이 저절로 생성되지 않는다는 큰 문제는 덤이었다.

때문에 결국 소정의 하드코딩을 섞어 다중 언어 지원 블로그를 구현하였다. 과정은 간단한데, 그 과정을 아래에 간략히 요약하고자 한다.

Página de presentación en coreano (arriba) y página de presentación en inglés (abajo) URL

La estructura es sencilla. Para aquellos que usan Jekyll, ya lo sabrán, las páginas de Jekyll se pueden acceder mediante **URL base** y **URL detallada**. En mi caso, la URL base corresponde a la página principal del blog, `slee333.github.io`, y la URL detallada es `about`.

El idioma se inserta entre la URL base y la URL detallada para redirigir a la página en el idioma correspondiente. Sin embargo, en el caso del idioma predeterminado que es coreano, se puede acceder al post o página directamente a través de `{URL base}/{URL detallada}` sin este proceso intermedio.

Hasta aquí han podido darse cuenta. <span style='color:blue'>_¿Qué es esto, simplemente crear dos páginas o posts, uno con la URL base y el otro con una URL que incluye /{idioma}/?_</span> Exacto. Asignemos el front matter de la siguiente manera.

![](https://prod-files-secure.s3.us-west-2.amazonaws.com/0401ca2c-0b04-4c4d-9f2f-d423516f4fae/f776eb0e-3278-4375-964e-5bdc6a0d4b51/Untitled.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Content-Sha256=UNSIGNED-PAYLOAD&X-Amz-Credential=AKIAT73L2G45HZZMZUHI%2F20240708%2Fus-west-2%2Fs3%2Faws4_request&X-Amz-Date=20240708T205734Z&X-Amz-Expires=3600&X-Amz-Signature=962364f14d329fe037212874153b3f46e58cc991fc35163253f938d489fb45d7&X-Amz-SignedHeaders=host&x-id=GetObject)

Front matter de la página en coreano (izquierda) y front matter de la página en inglés (derecha)

Después de especificarlo de esta manera, cuando el usuario cambia de idioma en la página de presentación, al cambiar de `kr` a `en`, se agrega `en` frente a /about/ y al cambiar de `en` a `kr`, se elimina `en` de la URL, permitiendo un intercambio fluido entre los idiomas. Además, también podrás ver que en el front matter de cada página se especifica el `lang` para indicar el idioma de la página, lo cual es un medio útil para reconocer el idioma actual de la página.

Arriba: front matter del post en coreano; abajo: front matter del post en inglés

El punto es configurar `permalink` como <span style='color:green'>/:title/</span>. En el caso de los posts en inglés, el `permalink` será naturalmente <span style='color:green'>/en/:title/</span>. Aquí, el título se refiere al nombre del archivo de la post en markdown. (por ejemplo, en el caso de la post **2024-07-01-나의 일기**, **나의 일기** se convierte en <span style='color:green'>:title</span> y el `permalink` del post será `/나의-일기`.) En resumen, si queremos ofrecer el mismo contenido de post en diferentes idiomas, siempre que los dos archivos tengan el mismo nombre, se puede proporcionar soporte multilingüe mediante la función <span style='color:green'>:title</span> y la adición de la ruta de URL del idioma.

Claro, puede surgir la siguiente pregunta.

> Si los dos archivos tienen el mismo nombre, ¿cómo los guardamos en la misma carpeta?

Es una observación válida. Por lo tanto, creamos una carpeta separada para cada idioma dentro de \_post para guardar los dos archivos por separado. Yo organizo mis posts dentro de \_post con carpetas separadas por idioma y categoría.

## 2. Crear un botón de cambio de idioma

Ahora que hemos creado dos páginas que corresponden a dos idiomas, es hora de crear un medio para ir de una página en un idioma a otra página en un idioma diferente dentro de la página. Yo creé un `header.html` en `root/_includes` y lo estaba usando como el header para todas las páginas/posts, y agregué el siguiente elemento al header.

![](https://prod-files-secure.s3.us-west-2.amazonaws.com/0401ca2c-0b04-4c4d-9f2f-d423516f4fae/fcb52e39-320b-4e11-b3b7-8a4883e76acb/Untitled.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Content-Sha256=UNSIGNED-PAYLOAD&X-Amz-Credential=AKIAT73L2G45HZZMZUHI%2F20240708%2Fus-west-2%2Fs3%2Faws4_request&X-Amz-Date=20240708T205734Z&X-Amz-Expires=3600&X-Amz-Signature=4087d62db64281108315678d4dbc90ff2ac6a929455484a4db244c549c6391d9&X-Amz-SignedHeaders=host&x-id=GetObject)

Como se muestra en el ejemplo anterior, solo existen kr y en como opciones, pero como soy ambicioso, también incluí español.

Este elemento div tiene el id `language-select` y funciona como un menú desplegable. Cuando la página actual está en coreano (`page.lang == 'kr'`), la opción con el value "kr" está seleccionada y viceversa, cuando la página está en inglés, la opción con el value 'en' está seleccionada. ## 3. Vincular la función de redirección al botón de cambio de idioma

Ahora es el momento de agregar la funcionalidad que redirige a la URL correspondiente al seleccionar otro idioma en este menú desplegable, como se mencionó anteriormente. Añadí el siguiente JavaScript en una etiqueta `<script>` dentro de `header.html`.

`<script>`

```javascript
// Selecciona el elemento language-select mencionado anteriormente.

const languageSelect = document.getElementById("language-select");

languageSelect.addEventListener("change", function () {
  // Cuando cambian las opciones en language-select, la función redirectPage recibe el valor actual como entrada.

  // Es decir, los valores de options "kr", "en", "es", etc., son introducidos.

  redirectPage(this.value);
});

// Función redirectPage.

function redirectPage(selectedLang) {
  let currentUrl = window.location.pathname;

  // Si la URL actual comienza con /en/ o /es/, se elimina esa parte.

  if (currentUrl.startsWith("/en/") || currentUrl.startsWith("/es/")) {
    currentUrl = currentUrl.replace(/^\/(en|es)\//, "/");
  }

  // Cuando el valor de entrada no es "kr", el idioma seleccionado (en este ejemplo es o en) se inserta al principio de la URL.

  if (selectedLang !== "kr") {
    currentUrl = `/${selectedLang}${currentUrl}`;
  }

  // Limpiar slashes redundantes.

  currentUrl = currentUrl.replace(/\/+/g, "/");

  // ¡Redirigir a la nueva URL!

  window.location.href = `${window.location.origin}${currentUrl}`;
}
```

`</script>`

## 4. Actualizar la barra de navegación

Ahora que lo pienso, no he explicado cómo cambian los menús (About, Life, etc.) de la barra de navegación superior al cambiar de idioma. El método más sencillo es usar hardcoded en la barra de navegación (esto es lo que hice al principio).

```html
<nav class="site-nav">
	<div class="menu-toggle" id="menu-toggle">&#9776;</div> <!-- Icono de hamburguesa -->
	<div class="trigger navbar">
		{% if page.lang == 'kr' %}
		<a class="page-link" href="{{ site.baseurl }}/about">소개</a>
		<a class="page-link" href="{{ site.baseurl }}/life">일상</a>
		<!-- Otros... -->
		{% endif %}
		{% if page.lang == 'en' %}
		<a class="page-link" href="{{ site.baseurl }}/en/about">About</a>
		<a class="page-link" href="{{ site.baseurl }}/en/life">Life</a>
		<!-- Otros... -->
		{% endif %}
		<!-- El language-switcher que usamos antes -->
		<div class="language-switcher">
			<select id="language-select">
				<option value="kr" {% if page.lang=='kr' %}selected{% endif %}>한국어</option>
				<option value="en" {% if page.lang=='en' %}selected{% endif %}>English</option>
				<option value="es" {% if page.lang=='es' %}selected{% endif %}>Español</option>
			</select>
		</div>
	</div>
</nav>

```

Utilizando la funcionalidad de if en Liquid para mostrar los menús en coreano si el idioma de la página es `kr`, y los menús en inglés si el idioma es `en`. Así también funciona perfectamente.

Ahora he cambiado el código a un método diferente que no utiliza hardcoded, pero detallaré esta parte en una publicación futura.
