Empecé este nuevo blog con una pequeña ambición: quería probar soportar el blog en coreano, inglés y ¡español! Al elegir una plataforma para comenzar el blog, opté por Jekyll, pero los complementos comunes como **multiple-languages-plugin** o **polyglot** presentaron varios problemas. Estos requerían que los posts y las páginas se almacenaran en subcarpetas, lo cual Jekyll no reconocía. Además, era un gran problema que no se generara automáticamente el sitemap.



Por lo tanto, terminé implementando un blog multilingüe mezclando un poco de hardcoding. El proceso es simple y quiero resumirlo brevemente a continuación.

La estructura es simple. Como muchos saben, las páginas en Jekyll se pueden acceder a través de una **URL base** y una **URL detallada**. En mi caso, la URL base es `slee333.github.io` y la URL detallada es `about`.



Si hay un idioma entre la URL base y la URL detallada, redirige a la página correspondiente en ese idioma. Sin embargo, en el caso del coreano (idioma base), se puede acceder directamente a la publicación o página a través de `{URL base}/{URL detallada}` sin este proceso. 



Hasta aquí, probablemente hayan notado algo. <span style='color:blue'>*¿Qué? ¿No es simplemente crear dos páginas o publicaciones y asignar una a una URL normal y otra a una URL con /{idioma}/?*</span> Sí, exactamente. Vamos a configurar el front matter de la siguiente manera.



![](https://prod-files-secure.s3.us-west-2.amazonaws.com/0401ca2c-0b04-4c4d-9f2f-d423516f4fae/f776eb0e-3278-4375-964e-5bdc6a0d4b51/Untitled.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Content-Sha256=UNSIGNED-PAYLOAD&X-Amz-Credential=AKIAT73L2G45HZZMZUHI%2F20240708%2Fus-west-2%2Fs3%2Faws4_request&X-Amz-Date=20240708T030435Z&X-Amz-Expires=3600&X-Amz-Signature=7f309656cb7fb1cbc3de116bc7dac69eb5e458eaac5b1eb8bb534a57c47fa05c&X-Amz-SignedHeaders=host&x-id=GetObject)

Front matter de la página en coreano (izquierda) y front matter de la página en inglés (derecha)



Después de configurar esto, cuando el usuario cambia el idioma dentro de la página de introducción, de `kr` a `en`, se agrega `en` antes de `/about/` y de `en` a `kr` se elimina `en` de la URL. Así podemos cambiar fácilmente de idioma entre las páginas. 



También se puede notar que cada página tiene un campo `lang` en el front matter para especificar el idioma de la página actual. Esto es útil para reconocer el idioma de la página actual.



### 1.1. En el caso de los posts

Arriba: front matter del post en coreano; Abajo: front matter del post en inglés



El punto es configurar el `permalink` como <span style='color:green'>/:title/</span>. En el caso de los posts en inglés, naturalmente el `permalink` será <span style='color:green'>/en/:title/</span>. Aquí, `title` se refiere al nombre del archivo markdown en el que se escribió el post. (por ejemplo: **2024-07-01-mi-diario** se convierte en **mi-diario** y el `permalink` del post será `/mi-diario`).



En resumen, para proporcionar el mismo post en diferentes idiomas, si los nombres de los dos archivos son iguales, soportar múltiples idiomas es posible a través de la función `:title` y agregando la URL del idioma.



Por supuesto, puede surgir esta pregunta:



> Si los nombres de los archivos son iguales, ¿cómo los guardamos en la misma carpeta?



Es una observación válida. Por lo tanto, creé carpetas de idiomas separadas dentro de _post para almacenar ambos archivos por separado. Organizo mis posts dentro de _post en carpetas según el idioma y la categoría.



![](https://prod-files-secure.s3.us-west-2.amazonaws.com/0401ca2c-0b04-4c4d-9f2f-d423516f4fae/0e182393-7e63-48ae-8abb-c5745169d85d/Untitled.png?X-Amz-Algorithm=AWS4-HMAC-SHA256&X-Amz-Content-Sha256=UNSIGNED-PAYLOAD&X-Amz-Credential=AKIAT73L2G45HZZMZUHI%2F20240708%2Fus-west-2%2Fs3%2Faws4_request&X-Amz-Date=20240708T030435Z&X-Amz-Expires=3600&X-Amz-Signature=2a04a074902d25575a1395f699e2a11797ea6d28178eadae050534d00f0cd3e5&X-Amz-SignedHeaders=host&x-id=GetObject)

Ahora que hemos creado dos páginas para los dos idiomas, es hora de crear un medio para cambiar entre las páginas en diferentes idiomas. Creé un `header.html` en `root/_includes` y lo usé como el header para todas las páginas/posts, añadiendo los siguientes elementos al header.

## 3. Conectar la función de redirección al botón de cambio de idioma



Ahora es el momento de agregar la funcionalidad de redirección cuando se selecciona otro idioma en el dropdown. Añadí el siguiente JavaScript dentro de una etiqueta `<script>` en `header.html`.



`<script>`



```javascript

// Selecciona el elemento language-select mencionado anteriormente.

const languageSelect = document.getElementById('language-select');

languageSelect.addEventListener('change', function () {

  // Cuando cambia la opción del language-select, se pasa el valor actual a la función redirectPage.

  redirectPage(this.value);

});

  

// Función redirectPage.

function redirectPage(selectedLang) {

  let currentUrl = window.location.pathname;



  // Si la URL actual comienza con /en/ o /es/, se elimina esa parte.

  if (currentUrl.startsWith('/en/') || currentUrl.startsWith('/es/')) {

    currentUrl = currentUrl.replace(/^\/(en|es)\//, '/');

  }



  // Si el idioma seleccionado no es "kr", se agrega el idioma seleccionado al principio de la URL.

  if (selectedLang !== 'kr') {

    currentUrl = `/${selectedLang}${currentUrl}`;

  }

  

  // Elimina duplicados del símbolo / en la URL.

  currentUrl = currentUrl.replace(/\/+/g, '/');



  // ¡Redirige a la nueva URL!

  window.location.href = `${window.location.origin}${currentUrl}`;

}

```



`</script>`

## 4. Actualizar la barra de navegación



Oh, me acabo de dar cuenta de que no expliqué cómo los menús en la barra de navegación (introducción, registros diarios, etc.) se cambian cuando se cambia el idioma. La forma más simple es usar hardcoding en la barra de navegación (yo comencé de esta forma también).



```html

<nav class="site-nav">

  <div class="menu-toggle" id="menu-toggle">&#9776;</div> <!-- Icono de hamburguesa -->

  <div class="trigger navbar">

      {% if page.lang == 'kr' %}

      <a class="page-link" href="{{ site.baseurl }}/about">소개</a>

        <a class="page-link" href="{{ site.baseurl }}/life">일상</a>

      <!-- Otros enlaces.. -->

      {% endif %}

      {% if page.lang == 'en' %}

      <a class="page-link" href="{{ site.baseurl }}/en/about">About</a>

        <a class="page-link" href="{{ site.baseurl }}/en/life">Life</a>

        <!-- Otros enlaces .. -->

      {% endif %}



	  <!-- El conmutador de idioma usado anteriormente -->

    <div class="language-switcher">

      <select id="language-select">

        <option value="kr" {% if page.lang=='kr' %}selected{% endif %}>한국어</option>

        <option value="en" {% if page.lang=='en' %}selected{% endif %}>English</option>

        <option value="es" {% if page.lang=='es' %}selected{% endif %}>Español</option>

      </select>

    </div>

  </div>

</nav>

```



Usando la funcionalidad if de Liquid, si el idioma de la página es kr, se mostrarán los menús en coreano; si es en, se mostrarán los menús en inglés. Este método funciona perfectamente bien.
