Starting a new blog this time, I had a small ambition. I wanted to support my blog in Korean, English, and Spanish (!).



For the platform to start the new blog, I chose Jekyll, but commonly used Jekyll plugins like **multiple-languages-plugin** or **polyglot** presented several difficulties for me. Posts and pages had to be stored in subfolders, but Jekyll did not recognize this aspect. Additionally, there was the significant problem of the site map not being generated automatically.



Therefore, I ended up implementing a multilingual-supporting blog with some hardcoding. The process is simple, and I will briefly summarize it below.

The structure is simple. As Jekyll users would know, Jekyll's pages can be accessed via **base URL** and **specific URL**. In my case, the base URL is `slee333.github.io`, which corresponds to the main page of the blog, and the specific URL is `about`.



If there is a language inserted between the base URL and the specific URL, it redirects to that language's page. However, for the default language, Korean, the post or page can be accessed directly via `{base URL}/{specific URL}` without this process.



By now, you would have realized it. <span style='color:blue'>*What's the big deal? You can just create two pages or posts and assign one with the regular URL and the other with the /{language}/ in the URL, right?*</span> Correct. Let's set the Front matter like this:

After specifying it this way, when the user changes the language on the introduction page, replace `kr` with `en` in front of /about/ and remove `en` from the URL for `en` → `kr` to facilitate language exchange between pages.



You'll also notice the `lang` specified in the Front matter to indicate the language of each page, which is useful as a means to recognize the current page's language.

The point is to set `permalink` to <span style='color:green'>/:title/</span>. For English posts, `permalink` will naturally become <span style='color:green'>/en/:title/</span>. Here, `title` refers to the filename of the markdown file in which the post is written. (e.g., **2024-07-01-my-diary** will have **my-diary** as <span style='color:green'>:title</span>, and the post's `permalink` will be `/my-diary`.)



In short, if posts providing the same content are offered in different languages, they can support multiple languages through the above-mentioned <span style='color:green'>:title</span> function and language URL inclusion, as long as the files have the same name.



Of course, you might ask:



> How can you store two files with the same name in the same folder?



A valid point. Therefore, separate language folders are created within _posts to store the two files differently. The author manages posts in _posts by creating folders for each language and category.

## 3. Linking the Redirection Function to the Language Switch Button



Now it's time to add a function to redirect to the corresponding URL when a different language is clicked on the dropdown, as mentioned above. I added the following JavaScript within the `<script>` tag in `header.html`:



`<script>`

```javascript

// Select the language-select element mentioned above.

const languageSelect = document.getElementById('language-select');

languageSelect.addEventListener('change', function () {

  // When the option of language-select changes, the redirectPage function is called with the current value as input.

  // That is, options' values such as "kr", "en", "es" are input.

  redirectPage(this.value);

});



// redirectPage function.

function redirectPage(selectedLang) {

  let currentUrl = window.location.pathname;



  // Remove the part of the URL that starts with /en/ or /es/.

  if (currentUrl.startsWith('/en/') || currentUrl.startsWith('/es/')) {

    currentUrl = currentUrl.replace(/^\/(en|es)\//, '/');

  }



  // If the input is not "kr", the selected language (e.g., es or en) is added to the front of the URL.

  if (selectedLang !== 'kr') {

    currentUrl = `/${selectedLang}${currentUrl}`;

  }



  // Clean up any duplicated / characters.

  currentUrl = currentUrl.replace(/\/+/g, '/');



  // Redirect to the new URL!

  window.location.href = `${window.location.origin}${currentUrl}`;

}

``` 

`</script>`

## 4. Updating the Navigation Bar



Oh, I forgot to explain how the top navigation bar menus (About, Daily Records, etc.) change when switching languages. The simplest method is to hardcode the navbar (this is how I initially approached it):



```html

<nav class="site-nav">

  <div class="menu-toggle" id="menu-toggle">&#9776;</div> <!-- Hamburger icon -->

  <div class="trigger navbar">

	  {% if page.lang == 'kr' %}

	  <a class="page-link" href="{{ site.baseurl }}/about">소개</a>

	  <a class="page-link" href="{{ site.baseurl }}/life">일상</a>

	  <!-- Etc .. -->

	  {% endif %}

	  {% if page.lang == 'en' %}

	  <a class="page-link" href="{{ site.baseurl }}/en/about">About</a>

	  <a class="page-link" href="{{ site.baseurl }}/en/life">Life</a>

	  <!-- Etc .. -->

	  {% endif %}



	  <!-- The previously used language-switcher -->

    <div class="language-switcher">

      <select id="language-select">

        <option value="kr" {% if page.lang=='kr' %}selected{% endif %}>한국어</option>

        <option value="en" {% if page.lang=='en' %}selected{% endif %}>English</option>

        <option value="es" {% if page.lang=='es' %}selected{% endif %}>Español</option>

      </select>

    </div>

  </div>

</nav>

```



Using Liquid's if function, if the page language is kr, Korean menus appear, and if it's en, English menus appear. This method works just fine.



I have later revised my approach from hardcoding, and I will describe this in more detail in a future post.
